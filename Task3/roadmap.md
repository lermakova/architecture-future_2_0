Этап 1 (Оценка и планирование):
Важно начать с анализа текущего состояния и проектирования новой архитектуры, чтобы понимать, какие изменения нужно внедрить. На этом этапе команда согласует, какие технологии использовать и как можно оптимизировать текущие процессы.
Этап 2 (Разделение системы на домены):
Разделение системы на домены одно из ключевых запланированных изменений. Необходимо для облегчения работы с данными и удобства доступа к ним.
Этап 3 (Разработка новых сервисов для новых направлений бизнеса):
Необхоимо разработать API-интерфейсы для новых бизнес-направлений.
Этап 4 (Создание интеграционного слоя с использованием Kafka):
Для обеспечения сбора данных в доменах будет создан новый интеграционный слой, заменяющий шину, используемую в старой архитектуре
Этап 5 (Миграция данных):
Для работы с имеющимися в системе данными имеет смысл провести их миграцию на новую архитектуру
Этап 6 (Внедрение API Gateway):
Внедрение API Gateway необходимо для централизованного доступа к сервисам 
Этап 7 (Развитие "витрин данных"):
Окончательная доработка витрин данных в соответствии с бизнес-требованиями
Этап 8 (Разработка портала самообслуживания):
Разработка сервиса доступа к данным, являющаяся завершающим этапом реорганизации системы доступа к данным
